## M5-B1 delivered behavior

Production changes are limited to:

- `dsh_runtime/state.py`
- `dsh_runtime/planner.py`
- `dsh_runtime/controller.py`

Test changes are limited to `tests/test_runtime.py`. The implementation adds
`TaskKind.REPOSITORY_CHANGE`, requires write authority and at least two
iterations, and implements this production Planner sequence:

    iteration 0 -> codebuddy
    iteration 1 -> codex read-only verifier
    iteration 2 -> terminal Decision

Planner interprets only the final non-empty verifier line after whitespace and
line-ending normalization:

    DSH_VERIFICATION: PASS -> terminal success Decision
    DSH_VERIFICATION: FAIL -> terminal failure Decision
    anything else -> terminal failure, "invalid verifier result"

The existing `Decision` gained backward-compatible `terminal_success=True` and
`terminal_error=None`. Controller remains the final TaskState owner and now
applies terminal success or terminal failure. DEFAULT, M3 continuation, and M4
read-only behavior remain intact.
