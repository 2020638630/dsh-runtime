## 当前已证明的 Runtime 形状

```text
DSHController
  ↓
Planner action Decision
  ↓
Executor one bounded invocation
  ↓
Plugin.execute()
  ↓
PluginResult
  ↓
Planner post-result Decision
  ↓
TaskState terminal transition
```

所有权必须保持：

- DSHController：business loop、invocation budget、continuation decision consumption、terminal TaskState transition。
- Planner：business-level action 或 terminal Decision。
- Executor：单次 invocation 的 timeout/cancellation governance、settlement、StopReason normalization。
- Plugin：单次 bounded native capability lifecycle。
- PluginResult：单次 invocation outcome，不控制业务 loop。
- TaskState：task lifecycle、invocation count、最终结果、latest successful invocation result。

## Milestone 3 当前契约

`Decision`：

```text
plugin != None -> action Decision
plugin == None -> terminal Decision
```

`TaskState`：

```text
iteration = settled Executor invocation attempts
max_iterations = invocation budget only
result = final successful task result only
last_invocation_result = one latest successful output for Planner
```

Controller 规则：

```text
max_iterations == 0
    -> skip Planner and invocation
    -> MAX_ITERATIONS

successful invocation
    -> iteration += 1
    -> store last_invocation_result
    -> Planner post-result evaluation

post-result terminal Decision
    -> commit final result
    -> COMPLETED

post-result action with remaining budget
    -> execute next invocation

post-result action at exhausted budget
    -> do not execute action
    -> MAX_ITERATIONS

FAILED / TIMED_OUT invocation
    -> iteration advances once
    -> terminal task state
    -> no continuation Planner evaluation
```

`SimplePlanner` 使用同一契约：初次返回 Echo action，Echo 成功后返回 terminal Decision。Controller 没有针对 `SimplePlanner` 或 `max_iterations == 1` 的特判。

initial terminal Decision 当前安全地落入既有 FAILED 边界；没有新增 no-op status。
